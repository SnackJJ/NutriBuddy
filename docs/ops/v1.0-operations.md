# V1.0 运维说明：费用闸、配额与白名单登录

> 对应 `docs/rfc/0010-cost-quota-and-allowlist.md`（S3）。人工步骤与可脚本化的步骤分开写：**本文中标「人工」的条目没有执行过**，agent 无法代做，上线前必须由人完成并在此确认。
>
> 三层防线（RFC 0010 §3.1）：provider 侧消费上限封顶总损失 → 白名单关掉注册面 → 配额限制已进来的人。三层缺一层都成立不了，且**前两层是人工的**。

## 1. 人工步骤（上线前必须完成）

1. **关闭公开注册（人工，待做）**
   Supabase Dashboard → Authentication → Sign In / Providers → Email：关闭 "Allow new users to sign up"。
   这一步是白名单方案 A 的全部机制（RFC 0010 §3.2）：关掉之后 `auth.signUp` 一律失败，只有持有 service role 的建号脚本能创建账号。
   同时确认 "Confirm email" 处于关闭状态：本项目的建号脚本以 `email_confirm: true` 建号，用户不会收到确认邮件。
   **验收**：用未建号的邮箱在 `/profile` 页面尝试注册 → 失败；账号只能由第 3 节的脚本创建。

2. **模型账号设消费上限（人工，待做）**
   在模型 provider 控制台设置消费上限 / 充值上限（ADR 0002「上线门槛 · 运维侧」第 1 条）。
   这是唯一能封顶总损失的措施：配额是软上限（RFC 0010 §3.3 明确接受并发超发），provider 上限才是硬上限。

3. **环境变量只给 Production（人工，待做）**
   Vercel → Settings → Environment Variables：`DEEPSEEK_API_KEY`、`SUPABASE_SERVICE_ROLE_KEY` 以及第 2 节的 `QUOTA_*` 只勾 Production，不给 Preview（ADR 0002 同节第 2 条）。

## 2. 部署侧配置（代码已读，人只需填值）

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `QUOTA_DAILY_TURNS` | `40` | 每 UTC 日允许的 turn 数 |
| `QUOTA_DAILY_COST_USD` | `1` | 每 UTC 日允许的累计模型花费 |
| `QUOTA_MAX_TURN_COST_USD` | `0.5` | 单轮最坏成本预估的上限 |
| ~~`NEXT_PUBLIC_SIGNUP_ENABLED`~~ | 已移除 | 注册入口不再靠自建开关：`/profile` 直接读 Auth 的公开设置（`GET /auth/v1/settings` 的 `disable_signup`）。Dashboard 那一个开关就是唯一真源 |

- 默认值写死在 `src/lib/quota.ts`（`QUOTA_DEFAULT_LIMITS`；单轮上限的取值口径见该处注释：正常请求的最坏预估 flash ≈ $0.07、pro ≈ $0.20），缺失或读不出来的值**回落到默认**而不是无限：写错一个环境变量不该把闸门打开。`0` 是合法值，含义见下。
- 注册入口跟随 Auth 的真实设置：读不到（网络/形状不对）一律按**关闭**渲染。理由同样是失败方向——「没人能注册」运维看得见，「所有人都在点一个必然失败的按钮」没人会报。
- 关闭注册时 `/profile` 不再显示 "Create account"，改为一句说明（`signupPolicy.ts` 的 `SIGNUP_CLOSED_MESSAGE`）。该文案不随邮箱变化，不构成 RFC 0010 §5 禁止的枚举线索。

## 3. 加人流程（脚本，可执行）

```bash
# 建号（不带 --password 时随机生成，只打印一次，请用私密渠道交付）
npx tsx --env-file=.env.local scripts/create-user.mts friend@example.com
npx tsx --env-file=.env.local scripts/create-user.mts friend@example.com --password '...'

# 看现在有哪些账号（邮箱 / 建号时间 / 是否确认 / 最后登录）
npx tsx --env-file=.env.local scripts/create-user.mts --list
```

（`package.json` 里建议加一条 `"create:user": "npx tsx --env-file=.env.local scripts/create-user.mts"`，加完即可 `npm run create:user friend@example.com`。）

脚本用 service role 走 `auth.admin.createUser`：service role 只在服务端与运维 shell 里存在，而公开的那扇门是 Dashboard 的注册开关——脚本走的是运维手里的钥匙，不是把门重新打开。

失败与退出码：`0` 成功；`1` Auth API 拒绝（邮箱已存在会单独说明）；`2` 缺配置或参数不合法。目标地址会打印在首行（本地栈会标注），环境变量优先于 `.env.local`（`scripts/lib/env.ts`），避免 `.env.local` 指向生产时静默建号。

尚未覆盖：**改密码 / 重置密码**也要走运维（Dashboard 或 admin API），应用本身没有找回密码入口；等有人真的需要再加。

## 4. 配额口径（代码已实现，此处只记口径）

- 计数来源是迁移 0011 的 `turns` 表，按 `(user_id, started_at)` 聚合，走 `turns_user_time_idx`。**不建计数表**：第二个聚合就是第二个真源（RFC 0010 §3.3 / issue #98）。
- 日界按 **UTC**；计数含当天所有 turn，包含失败轮（`turn_start` 已建行）。
- 被拒请求**不调用模型、不写 turn 行**，因此对自己产生的计数不可见（RFC 0010 §5）。
- `limit = 0` 表示该维度**一律拒绝**（`current >= limit` 即刻成立）：把某个预算设成 0 是紧急关闸，不是「放一轮免费」。
- 判定顺序 `turn_cost` → `daily_cost` → `daily_turns`：单轮过贵是请求自身的属性（不查库即可答），成本先于轮数是因为 §9.2 让成本成为约束预算——429 里的 `scope` 应当指向真正卡住的那个预算。
- 超限形态：HTTP 429 + `{ error, scope, limit, current, resetAt }`，`resetAt` 是下一个 UTC 零点。
- 计数源读不出来时**失败关闭**（503 `quota_check_unavailable`）：源挂了就放行的闸不是闸，而且这种状态下这轮本来也存不下轨迹。

## 5. 拒绝的可观测（issue #103）

每次拒绝写一行结构化日志，单行 JSON，便于 grep 与统计：

```
[quota] {"user_id":"…","scope":"daily_turns","limit":40,"current":40,"path":"/api/chat","at":"2026-07-27T12:00:00.000Z"}
```

计数源不可用时另写一行 `[quota] {"user_id":…,"path":…,"at":…,"cause":…}`。
V1.0 **只 log，不落库**（RFC 0010 §9 未决 3）：需要滥用可见性时再加 `rejections` 表。

常用检索：

```bash
# 今天被拒的人与维度
grep '\[quota\]' <log> | grep '"at":"2026-07-27'
# 被日成本预算卡住的次数
grep '\[quota\]' <log> | grep -c '"scope":"daily_cost"'
```

## 7. 遗留与校准点

1. ~~**单轮最坏成本预估的「证据子集」项按 0 计入**~~ —— **已校准（2026-09-15）**。该项曾是已知漏计（S3 与 S4 并行落地，issue #100 的第二遍修改点）。现在按 `PINNED_MAX_CHARS`（24000 字符 → 12000 token，同一常量由 `PinnedBudgetError` 强制）计入，常量从 `pinnedSet.ts` 派生而非抄写，因此语料长大不会让它失效。**上界因此抬高一档**：每轮最多多算 `8 × 12000` 个 prompt token，在 miss 价下 +$0.0269（flash）/ +$0.0538（pro），即 §2 里记的约 $0.07 / $0.20 变成约 **$0.097 / $0.254** —— 仍低于 `QUOTA_MAX_TURN_COST_USD` 默认的 `0.5`，但这个余量从 7× 缩到 2×，若要调 `QUOTA_MAX_TURN_COST_USD` 请对照这两个数。`tests/quota.test.ts` 里有一条测试专门断言"满上限语料仍低于默认闸门"。
2. `turns` 表 `cost_usd` 只在 `turn_end` 写入，因此**进行中的轮**计为 1 turn、$0：与 §3.3 接受的并发超发同向，且不再造一个 TypeScript 侧成本聚合（RFC 0008 §3.4）。
3. 客户端目前不识别 429 的 typed body，会把 `quota_exceeded` 原样显示；RFC 0010 §9 未决 4 决定 V1.0 不做配额 UI（也不展示剩余额度），故未改。
4. 自动化覆盖：配额判定与边界、`turns` 聚合、路由前置顺序、最坏成本预估、拒绝日志行、UI 隐藏注册入口均有单测（`tests/quota.test.ts`、`tests/dailyUsage.test.ts`、`tests/signupPolicy.test.ts`）。**没有**端到端 429 验证（需要真人带真实 session 打到部署实例），本节第 1、2 条人工步骤同样没有执行过。
